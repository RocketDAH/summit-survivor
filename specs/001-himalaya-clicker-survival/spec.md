# Feature Specification: 정상까지 (Summit Survivor)

**Feature Branch**: `001-himalaya-clicker-survival`

**Created**: 2026-06-01

**Updated**: 2026-06-02

**Status**: Draft

**Input**: 웹 기반 실시간 서바이벌 클릭커 게임. 자동 등반하며 1.5초마다 나타나는 아이템을 선택/회피하여 2분 내 정상(3,000m) 도달

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 게임 시작 및 자동 등반 (Priority: P1)

플레이어가 게임을 시작하면 캐릭터가 자동으로 산을 등반하기 시작한다. 플레이어는 이동 조작 없이 오직 아이템 선택과 생존에만 집중한다.

**Why this priority**: 게임의 핵심 루프로, 자동 등반이 없으면 게임이 성립하지 않음

**Independent Test**: 게임 시작 후 캐릭터가 자동으로 고도가 올라가는지 확인

**Acceptance Scenarios**:

1. **Given** 플레이어가 메인 화면에 있을 때, **When** 시작 버튼을 클릭하면, **Then** 2분 타이머와 HP 100으로 게임이 시작되고 캐릭터가 자동 등반을 시작한다
2. **Given** 게임이 진행 중일 때, **When** 시간이 흐르면, **Then** 캐릭터의 고도가 자동으로 증가한다
3. **Given** 게임이 진행 중일 때, **When** 매 초마다, **Then** HP가 1씩 자동 감소한다

---

### User Story 2 - 이벤트 선택 시스템 (Priority: P1)

1.5초마다 아이템/이벤트가 나타나고, 플레이어는 1.5초 내에 선택 여부를 결정해야 한다. 선택하지 않으면 자동으로 무시된다.

**Why this priority**: "1.5초마다 찾아오는 선택의 순간"이 게임의 핵심 컨셉

**Independent Test**: 1.5초 간격으로 이벤트가 나타나고 선택/무시가 작동하는지 확인

**Acceptance Scenarios**:

1. **Given** 게임이 진행 중일 때, **When** 1.5초가 경과하면, **Then** 새로운 아이템/이벤트가 화면에 나타난다
2. **Given** 아이템이 화면에 나타났을 때, **When** 플레이어가 1.5초 내에 클릭하면, **Then** 해당 아이템의 효과가 적용된다
3. **Given** 아이템이 화면에 나타났을 때, **When** 1.5초 내에 선택하지 않으면, **Then** 아이템이 자동으로 무시되고 다음 이벤트가 발생한다

---

### User Story 3 - 체력 및 생존 관리 (Priority: P1)

플레이어는 HP를 관리하며 생존해야 한다. HP가 0이 되면 즉시 게임 오버.

**Why this priority**: 생존이 게임의 핵심 긴장감을 제공

**Independent Test**: HP 감소/회복이 정상 작동하고, HP 0에서 게임 오버되는지 확인

**Acceptance Scenarios**:

1. **Given** 게임이 진행 중일 때, **When** HP가 0에 도달하면, **Then** 즉시 게임이 종료되고 패배 화면이 표시된다
2. **Given** 플레이어가 긍정 아이템(음식 등)을 선택했을 때, **When** 효과가 적용되면, **Then** HP가 회복된다
3. **Given** 플레이어가 부정 아이템(낙석 등)을 선택했을 때, **When** 효과가 적용되면, **Then** HP가 감소한다

---

### User Story 4 - 게임 결과 및 점수 (Priority: P1)

2분 내 정상(3,000m) 도달 시 승리. 점수는 기본 점수 + 생존 시간 + 남은 체력 + 정상 도달 보너스로 계산된다.

**Why this priority**: 목표와 성취감을 제공하는 핵심 요소

**Independent Test**: 정상 도달 시 승리, 점수 계산이 정확한지 확인

**Acceptance Scenarios**:

1. **Given** 게임이 진행 중일 때, **When** 고도가 3,000m에 도달하면, **Then** 승리 화면과 함께 최종 점수가 표시된다
2. **Given** 게임이 종료되었을 때, **When** 결과 화면이 표시되면, **Then** 기본 점수, 생존 보너스, 체력 보너스, 정상 보너스가 계산되어 표시된다
3. **Given** 2분이 경과했을 때, **When** 정상에 도달하지 못했다면, **Then** 도달한 고도와 점수가 표시된다

---

### User Story 5 - 리더보드 (Priority: P2)

플레이어의 최고 점수와 기록이 리더보드에 저장되어 경쟁 요소를 제공한다.

**Why this priority**: 리플레이 가치와 경쟁 동기 부여

**Independent Test**: 게임 종료 후 점수가 리더보드에 반영되는지 확인

**Acceptance Scenarios**:

1. **Given** 게임이 종료되었을 때, **When** 점수가 계산되면, **Then** 리더보드에 플레이어 이름, 점수, 클리어 기록이 저장된다
2. **Given** 메인 화면에서, **When** 리더보드를 확인하면, **Then** 상위 랭킹 플레이어 목록이 표시된다

---

### User Story 6 - 재시작 (Priority: P2)

게임 종료 후 즉시 재도전 가능.

**Why this priority**: 빠른 리플레이로 중독성 확보

**Independent Test**: 결과 화면에서 재시작이 작동하는지 확인

**Acceptance Scenarios**:

1. **Given** 결과 화면이 표시되었을 때, **When** 재시작 버튼을 클릭하면, **Then** 새로운 게임이 즉시 시작된다

---

### Edge Cases

- 1.5초 이벤트 도중 브라우저 탭이 비활성화되면? → 타이머와 HP 감소는 계속 진행
- 동시에 여러 번 빠르게 클릭하면? → 현재 이벤트에 대해 한 번만 처리
- 네트워크 연결이 끊기면? → 게임 플레이는 로컬에서 진행, 리더보드 저장만 실패 가능

## Requirements *(mandatory)*

### Functional Requirements

**자동 등반 시스템**
- **FR-001**: 게임 시작 시 캐릭터가 자동으로 등반을 시작해야 한다 (별도 이동 조작 없음)
- **FR-002**: 고도는 시간에 따라 자동으로 증가해야 한다

**체력 시스템**
- **FR-003**: 초기 HP는 100이어야 한다
- **FR-004**: HP는 초당 1씩 자동 감소해야 한다
- **FR-005**: HP가 0에 도달하면 즉시 게임이 종료되어야 한다

**이벤트 시스템**
- **FR-006**: 1.5초마다 새로운 아이템/이벤트가 발생해야 한다
- **FR-007**: 플레이어는 1.5초 내에 선택 여부를 결정해야 하며, 미선택 시 자동 무시 처리된다

**아이템 시스템**
- **FR-008**: 긍정 아이템(45%)은 체력 회복, 생존 보조, 위험 회피 효과를 제공해야 한다
- **FR-009**: 부정 아이템(35%)은 체력 감소, 생존 난이도 증가 효과를 가져야 한다
- **FR-010**: 랜덤 아이템(20%)은 대량 회복 또는 대량 피해의 고위험 고보상 구조여야 한다

**점수 시스템**
- **FR-011**: 최종 점수 = 기본 점수(획득 아이템 수) + 생존 시간 보너스 + 남은 체력 보너스 + 정상 도달 보너스로 계산되어야 한다

**게임 종료 조건**
- **FR-012**: 승리 조건: 2분 이내 정상(3,000m) 도달
- **FR-013**: 패배 조건: HP 0 도달

**리더보드**
- **FR-014**: 플레이어 이름, 최고 점수, 클리어 기록을 저장하고 표시해야 한다

### Key Entities

- **플레이어 상태**: 현재 고도(0~3,000m), HP(0~100), 획득 아이템 수, 생존 시간
- **이벤트/아이템**: 종류(긍정/부정/랜덤), 이름, 효과 유형, 효과 수치, 발생 확률
- **게임 세션**: 남은 시간(120초), 현재 고도, HP, 점수, 게임 상태(진행/승리/패배)
- **점수**: 기본 점수, 생존 보너스, 체력 보너스, 정상 보너스, 최종 점수
- **리더보드 엔트리**: 플레이어 이름, 최고 점수, 획득 칭호, 클리어 여부

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 이벤트는 정확히 1.5초 간격으로 발생한다
- **SC-002**: HP는 정확히 초당 1씩 감소한다
- **SC-003**: 게임 세션은 최대 2분(120초) 동안 진행된다
- **SC-004**: 아이템 분포는 긍정 45%, 부정 35%, 랜덤 20% 비율을 따른다
- **SC-005**: 플레이어는 게임 종료 후 3초 이내에 재시작할 수 있다
- **SC-006**: 적절한 플레이 시 정상 도달 확률은 30~50% 사이를 유지한다
- **SC-007**: 90% 이상의 신규 플레이어가 첫 플레이에서 게임 규칙을 이해한다

## Assumptions

- 대상 사용자는 안정적인 인터넷 연결이 있는 PC 또는 모바일 웹 브라우저 사용자이다
- MVP에서는 단일 스테이지(기본)만 구현하며, 스테이지 시스템은 후순위이다
- MVP에서는 캐릭터 시스템(등산가, 마라토너, 요리사, 탐험가)은 후순위이다
- MVP에서는 칭호 시스템(스피드러너, 철인, 생존왕)은 후순위이다
- 사운드/음악은 v1 범위 외이다
- SNS 공유 기능은 후순위이다

## MVP vs 후순위 기능

### MVP (반드시 구현)
- 자동 등반
- 체력 시스템 (100 HP, 초당 1 감소)
- 이벤트 생성 (1.5초 주기)
- 아이템 선택 (긍정/부정/랜덤)
- 점수 계산
- 게임 종료 (승리/패배)
- 리더보드

### 후순위
- 캐릭터 시스템 (등산가, 마라토너, 요리사, 탐험가)
- 스테이지 해금 (한라산 → 백두산 → 에베레스트 → 화산섬)
- 칭호 시스템 (스피드러너, 철인, 생존왕)
- SNS 공유
- 멀티플레이 (1:1 실시간 레이스)
- 시즌제 랭킹

## 아이템 예시

### 긍정 아이템 (45%)
| 아이템 | 효과 |
| ------ | ---- |
| 식량 | HP 회복 |
| 물 | HP 회복 |
| 텐트 | 생존 보조 |

### 부정 아이템 (35%)
| 아이템 | 효과 |
| ------ | ---- |
| 낙석 | HP 감소 |
| 폭풍 | HP 감소 |
| 부상 | HP 감소 |

### 랜덤 아이템 (20%)
| 아이템 | 효과 |
| ------ | ---- |
| 보물상자 | 대량 회복 또는 대량 피해 |
| 버섯 | 대량 회복 또는 대량 피해 |
| 미확인 물품 | 특수 효과 |
