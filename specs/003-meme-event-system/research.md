# 리서치: 밈 이벤트 시스템

**기능**: 003-meme-event-system  
**날짜**: 2026-06-06

## 1. 이벤트 생성 알고리즘

### 결정: 상황 기반 딜레마 페어링

**이유**: 
- 단순 랜덤 생성은 의미 있는 선택을 보장하지 않음
- 플레이어 상태(HP, 고도, 콤보, 버프)에 따라 적절한 딜레마 제공 필요

**대안 검토**:
| 방식 | 장점 | 단점 | 결정 |
|------|------|------|------|
| 완전 랜덤 | 구현 간단 | 재미없는 선택지 많음 | ❌ |
| 가중치 랜덤 | 밸런스 조절 가능 | 딜레마 보장 안됨 | ❌ |
| 상황 기반 페어링 | 항상 의미 있는 선택 | 구현 복잡 | ✅ |
| 사전 정의 이벤트 | 밸런스 완벽 | 반복 플레이 시 예측 가능 | ❌ |

**구현 방향**:
```typescript
type Scenario = 'normal' | 'crisis' | 'sprint' | 'rescue' | 'combo';

function determineScenario(state: GameState): Scenario {
  if (state.hp < 30) return 'crisis';
  if (state.altitude > 2000) return 'sprint';
  if (state.debuffs.length > 0) return 'rescue';
  if (state.combo >= 2) return 'combo';
  return 'normal';
}
```

## 2. 콤보 시스템

### 결정: 카테고리 기반 연속 선택 보너스

**이유**:
- 전략적 깊이 추가 (콤보 유지 vs 더 좋은 아이템)
- 아이템 분류의 의미 부여
- 리플레이 가치 증가

**보너스 곡선 분석**:
| 콤보 수 | 선형 (+10%/콤보) | 지수 (×1.25) | **채택 (고정 구간)** |
|---------|-----------------|--------------|---------------------|
| 2 | +20% | +25% | **+25%** |
| 3 | +30% | +56% | **+50%** |
| 4 | +40% | +95% | **+100%** |
| 5+ | +50% | +144% | **+100% + 특수효과** |

**선택 이유**: 고정 구간 방식이 플레이어가 예측하기 쉽고, 4콤보 이상은 도달하기 어려우므로 동일한 최대 보너스로 고정.

## 3. 버프/디버프 시스템

### 결정: Zustand 스토어 + 타이머 기반 만료

**이유**:
- 기존 gameStore와 통합 용이
- React 렌더링과 자연스럽게 연동
- 여러 버프 동시 관리 가능

**대안 검토**:
| 방식 | 장점 | 단점 | 결정 |
|------|------|------|------|
| setInterval | 간단 | 메모리 누수 위험, 정확도 낮음 | ❌ |
| requestAnimationFrame | 부드러움 | 탭 비활성 시 문제 | ❌ |
| **게임 루프 통합** | 일관성, 정확도 | 추가 로직 필요 | ✅ |

**버프 데이터 구조**:
```typescript
interface ActiveBuff {
  id: string;
  type: BuffType;
  remainingTime: number;  // 초 단위
  usesLeft?: number;      // 1회성 버프용
}
```

**중첩 규칙**:
- 같은 버프: 시간 갱신 (중첩 X)
- 상반 효과: 상쇄
- 최대 동시 버프: 3개 (UI 가독성)

## 4. 자동 선택 시스템

### 결정: 시간 초과 시 50:50 랜덤 선택

**이유**:
- 게임 흐름 유지 (멍때려도 진행)
- 긴장감 추가 (운에 맡기는 리스크)
- "무시" 옵션 제거로 단순화

**대안 검토**:
| 방식 | 장점 | 단점 | 결정 |
|------|------|------|------|
| 둘 다 놓침 | 페널티 없음 | 지루함, 전략 없음 | ❌ |
| 항상 왼쪽/오른쪽 | 예측 가능 | 전략적으로 악용 가능 | ❌ |
| **50:50 랜덤** | 긴장감, 공정함 | 운 요소 추가 | ✅ |
| 나쁜 쪽 선택 | 페널티 | 너무 가혹함 | ❌ |

## 5. 아이템 밸런스

### 결정: HP 120 기준, 클리어율 40-50% 타겟

**밸런스 시뮬레이션**:

| 시나리오 | HP 변화/이벤트 | 2분간 순 HP | 생존 가능 |
|----------|---------------|-------------|----------|
| 최악 (모든 부정) | -15 평균 | -1200 | ❌ |
| 운 나쁨 (40:60) | -3 평균 | -240 | ❌ |
| **균형 (50:50)** | 0 평균 | ±0 | ⚠️ |
| 운 좋음 (60:40) | +3 평균 | +240 | ✅ |
| 최고 (모든 긍정) | +15 평균 | +1200 | ✅ |

**분석**: 
- HP 120 시작, 초당 -1 감소 → 2분간 -120
- 80회 이벤트, 평균 +0 HP/이벤트면 생존 불가
- 평균 +1.5 HP/이벤트 필요 → 긍정:부정 = 55:45
- 고도별 난이도 조절로 초반 쉽게, 후반 어렵게

**결론**: 
- 0-1000m: 60:40 (긍정 우위)
- 1000-2000m: 50:50 (균형)
- 2000-3000m: 40:60 (부정 우위)

## 6. UI/UX 레이아웃

### 결정: 2지선다 카드 + 사이드바 버프 로그

**이유**:
- 양자택일의 시각적 명확성
- 버프 상태의 실시간 모니터링
- 선택 히스토리로 복기 가능

**레이아웃 구성**:
```
┌────────────────────────────────────────────────────┐
│ 상태바 (HP, 고도, 시간, 콤보)                       │
├──────────────────────────────────┬─────────────────┤
│                                  │ 버프 로그       │
│   [왼쪽 아이템]  VS  [오른쪽 아이템]│ - 활성 버프    │
│                                  │ - 히스토리     │
│         [타이머 바]              │                │
├──────────────────────────────────┴─────────────────┤
│ 등반 비주얼 (배경)                                  │
└────────────────────────────────────────────────────┘
```

**반응형 고려**:
- 모바일: 사이드바 → 하단 접이식 패널
- 터치: 카드 스와이프로 선택
