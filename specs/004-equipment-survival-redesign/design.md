# Summit Survivor — 장비 기반 생존 리디자인 (Design v0.1)

> 목적: "게임이 혼자 플레이되는" 현재 구조를 **장비로 빌드를 쌓고(성장) → 환경 위협으로 시험받는(긴장)** 로그라이트 루프로 재설계한다.
> 이 문서는 팀 합의 + 구현 착수용 초안이다. 모든 수치는 **제안값(조정 가능)** 이며 `밸런스` 표에 모아두었다.

---

## 0. 한눈에 보기 (TL;DR)

- **핵심 루프**: `빌드(멈춤·선택) → 등반(실시간·위협) → 빌드 → … → 정상(3000m) 또는 사망(HP 0)`
- **선택은 멈춘다**: 선택지가 뜨면 등반이 멈추고 플레이어가 집중. 단, **선택은 매 1.5초가 아니라 고도 500m 구간마다**.
- **성장 체감**: 성장은 "선택"이 아니라 **선택 사이의 등반 구간**에서 체감된다. 장비가 캐릭터에 보이고, 과거에 무섭던 위협이 무력화된다.
- **장비(영구)** = 환경 위협 방어 + 스탯(최대HP/속도). **소비(1회용)** = 회복 + 돌발(동물) 대응.
- **디버프 = 환경 이벤트**: 등반 중 랜덤 발생, 장비가 있으면 자동 면제.

## 1. 게임 루프 상세

### 1.1 두 레이어 분리

| 레이어 | 상태 | 역할 | 발생 |
|---|---|---|---|
| 🏗 **빌드 레이어** | **일시정지** | 장비/소비/스탯 획득 (신중한 선택) | 고도 500m 구간마다 + 시작 시 |
| 🧗 **등반 레이어** | **실시간** | 자동 등반 + 환경 위협 자동 처리 | 계속 |

### 1.2 등장 빈도 — "파워 획득"과 "참여"를 분리 (페이싱 핵심)

> "자주 나오면 쉽고, 안 나오면 노잼" 딜레마는 **하나의 빈도로 다 처리하려 해서** 생긴다.
> 등장물을 3종류로 쪼개면, 참여는 잦게 / 파워는 통제되게 동시에 잡힌다.

| 종류 | 빈도 | 멈춤? | 왜 이 빈도인가 |
|---|---|---|---|
| 🛡 **장비** (영구 파워) | **드물게** — 500m 구간마다 (런당 6회) | **O (유일한 멈춤)** | 영구라서 자주 주면 눈덩이 → 쉬워짐 |
| 💊 **소비** (1회용) | **자주** — 200m마다 등장 (~12회) | X (무정지 줍기) | 써서 없어지니 누적 안 됨 → 자주 줘도 안 쉬움. 밸런스는 위협으로 조정 |
| ⛈ **위협** (파워 소모) | **계속** — 6~8초마다 | X (전부 자동) | 파워를 *주는 게 아니라 시험* → 자주 줄수록 어려워짐 |

**→ 게임이 멈추는 건 장비 선택 6회뿐.** 소비·위협·동물은 전부 자동 처리되고, 플레이어는 그 사이 **빌드가 작동하는 걸 지켜보며** 다음 장비 선택을 노린다.

#### 자동화 규칙 (멈춤 없음)
- **소비 줍기**: 등장 시 자동으로 가방에 담음. 가방이 꽉 차면 **가장 약한 소비를 자동 교체**(알림만 표시).
- **소비 사용**: 자동. HP가 임계값 이하로 떨어지면 회복템 자동 사용, 동물 출현 시 방어템 자동 사용. *(수동 사용 버튼은 선택적 폴리시)*
- **동물 위협**: 반응형 멈춤 없음. 방어템 있으면 자동 소모, 없으면 자동 피해.
- **환경 위협**: 장비 있으면 자동 면제(연출), 없으면 자동 피해.

> ⚠️ 에이전시가 **장비 6선택에 집중**되므로, 그 선택은 충분히 풍부하고 무겁게(슬롯/티어/면제 트레이드오프) 설계해야 한다.

#### 자주 나와도 안 쉬운 3가지 구조적 장치 (반드시 시스템에 내장)
1. **장비 = 슬롯제 → 파워 상한 존재.** 슬롯 6개·각 1개. 같은 슬롯은 교체(업글)만, 무한 누적 불가. 천장 = "6슬롯 T3".
2. **소비 = 보유 칸 제한 → 비축 불가.** 자주 주워도 등 슬롯 2~4칸. "주울까/바꿀까/지금 쓸까"만 늘고 파워는 안 폭증.
3. **위협 = 상시 상쇄.** 고도 비례 드레인 + 후반 곰/번개. 빌드가 세지는 만큼 산도 세진다.

#### 거리 기반의 장점
장비를 **시간이 아니라 거리(500m)** 에 묶음 → 속도를 올려 빨리 가도 **런당 장비 수는 6개로 고정**. "빨리 갔더니 파워 폭증"이 원천 차단(속도 vs 파밍 트레이드오프 유지).

### 1.2.1 한 판 타임라인

```
[0m] 시작: 🛡장비 1택 (멈춤)
 200 💊  400 💊  [500 🛡]  600 💊  800 💊  [1000 🛡*]
 1200 💊 1400 💊 [1500 🛡] 1600 💊 1800 💊 [2000 🛡*]
 2200 💊 2400 💊 [2500 🛡] 2600 💊 2800 💊 [3000 🏆 정상→승리]
        ↑ 그 사이 6~8초마다 ⛈위협이 계속 끼어듦   ※ 도중 HP 0 → 💀 사망
   * 1000·2000m은 장비 구간과 겹침 → 장비 우선(소비 생략)
```

- **장비 선택**: 시작 1 + 500m 구간 5 = **총 6회** (영구 파워)
- **소비 등장**: 200m마다 = **~12회** (장비와 겹치는 1000·2000m, 정상 3000m 제외). 보유 칸 제한으로 비축 불가
- **위협**: 평균 6~8초마다 랜덤. 환경=자동 면제/피해, **동물=자동 대응**(방어템 자동 소모 or 자동 피해, 4.3)
- 빈도/오프셋은 ±랜덤 지터 허용 (기계적 반복 방지)

### 1.3 "성장 체감"을 만드는 5가지 장치 (필수 구현)

1. **장비가 캐릭터에 보인다** — 페이퍼돌. 장비 획득/교체 시 캐릭터 스프라이트 변화.
2. **스탯 바가 자란다** — 최대 HP 바가 길어지고, 속도 미터가 올라간다.
3. **회고적 보상** — 과거에 무섭던 위협이 무력화될 때 연출: `🌧 비! → 🧥 우비 발동, 피해 면제!`
4. **위협 에스컬레이션** — 고도가 오를수록 위협이 강해진다(비→눈→곰→번개). 내 장비가 산을 따라잡는 레이스.
5. **선택이 드물고 멈춘다** — 매 선택이 무겁다. (1.5초 난사 제거)

## 2. 스탯 시스템

| 스탯 | 시작값 | 의미 | 성장 수단 |
|---|---|---|---|
| **최대 HP** | **100 → 최대 120 (하드 캡)** | 위협을 버티는 총량 | 장비(머리/몸통/등)·스탯 카드, 단 **120에서 클립** |
| **현재 HP** | = 최대 HP | 0이면 사망 | 소비템 회복 |
| **속도(speed)** | 25 m/s | 등반 속도 = 정상 도달 시간 | 장비(발/손), 에너지젤 |
| **HP 드레인** | 고도 비례 (아래) | 고산병/피로 | 갓생/존버 버프로 완화 |

> **최대 HP 설계 의도**: 100 시작, **120이 천장**. HP 성장폭은 +20으로 좁다(=HP는 끝까지 빠듯). 따라서 **장비의 진짜 가치는 HP 수치가 아니라 "면제 + 속도"**. 큰 HP 풀로 안전해지는 게임이 아니라, *위협을 아예 안 맞게 만드는* 게임. `maxHp = min(120, 100 + Σ보너스)`, 최대HP 증가 시 현재 HP도 같은 양 즉시 +.

### 2.1 HP 드레인 = 고도 비례 (핵심 변경, 2분 런 기준)

> 시간 일정 드레인(현재 1/s)을 버리고 **고도가 높을수록 가혹**하게. 후반 = 진짜 위험 구간.
> 2분 런 + HP 풀 100~120에 맞춰 낮게 재조정.

| 고도 구간 | 드레인 |
|---|---|
| 0 ~ 1000m | 0.3 / s |
| 1000 ~ 2000m | 0.5 / s |
| 2000 ~ 3000m | 0.8 / s |

> 패시브 드레인만으로 기본 ~64 HP 소모(40s×3구간 기준). 나머지는 위협이 깎고 소비가 메운다 → HP가 늘 빠듯.

### 2.2 등반 속도 (런 길이 2분)

- 기본 **25 m/s → 3000m ÷ 25 = 120초(2:00)** 베이스 런타임.
- 발/손 장비로 ~35 m/s(약 85초)까지 단축 → "스피드런" 빌드.
- `슬로우`(비/눈/빙판) 발생 시 속도 ×0.5 일시 적용.
- **트레이드오프**: 빠르면 위협(시간 기반)도 덜 만나지만, 그만큼 소비·회복 기회도 줄어든다.

### 2.3 승패 조건

- **승리**: 고도 ≥ 3000m
- **패배**: HP ≤ 0
- **시간**: 별도 타임아웃 패배 없음. 런은 자연히 ~2분. 클리어 타임은 **점수 보너스**(빠를수록 가점).

## 3. 장비 시스템 (영구 · 슬롯)

### 3.1 슬롯 (6종, MVP는 ★ 3종부터)

| 슬롯 | 주 스탯 | 면제 위협 |
|---|---|---|
| 🧢 머리 | 최대 HP | 낙석/우박 |
| ★🧥 몸통 | 최대 HP | 비 / 추위 |
| ★🥾 발 | 속도 | 눈 / 빙판 |
| 🧤 손 | 속도 | 절벽 |
| ★🎒 등(가방) | 소비 슬롯 수 + 최대 HP | — |
| 🧿 액세서리 | 특수 | 동물 조우 확률 |

### 3.2 장비 티어 (같은 슬롯 상위 티어 = 교체 업그레이드)

> **HP 보너스는 작게** 잡았다(최대 HP 캡 120 = 헤드룸 +20). 장비 가치의 핵심은 HP가 아니라 **면제·속도**.

**🧢 머리**
| 티어 | 이름 | 효과 |
|---|---|---|
| T1 | 비니 | 최대HP +4 |
| T2 | 등산모 | 최대HP +5, 낙석 피해 -50% |
| T3 | 헬멧 | 최대HP +6, 낙석 면제 |

**🧥 몸통** ★
| 티어 | 이름 | 효과 |
|---|---|---|
| T1 | 바람막이 | 최대HP +6 |
| T2 | 우비 | 최대HP +4, **비 면제** |
| T3 | 패딩 | 최대HP +8, **비·추위 면제** |

**🥾 발** ★
| 티어 | 이름 | 효과 |
|---|---|---|
| T1 | 운동화 | 속도 +3 |
| T2 | 등산화 | 속도 +5, **빙판 면제** |
| T3 | 아이젠 | 속도 +8, **빙판·눈 면제** (단, 번개 확률 ↑) |

**🧤 손**
| 티어 | 이름 | 효과 |
|---|---|---|
| T1 | 장갑 | 속도 +2, 최대HP +3 |

**🎒 등(가방)** ★ — 소비 슬롯 수 결정
| 티어 | 이름 | 효과 |
|---|---|---|
| T1 | 보조가방 | 소비 2칸, 최대HP +2 |
| T2 | 등산배낭 | 소비 3칸, 최대HP +4 |
| T3 | 대형배낭 | 소비 4칸, 최대HP +6 |

**🧿 액세서리**
| 이름 | 효과 |
|---|---|
| 나침반 | 위험 이벤트 확률 -10% |
| 곰방울 | 동물 조우 확률 -50% |
| 행운부적 | 환경 피해 1회 방어(쿨다운 30s) |

> **설계 포인트**: 상위 위협(눈보라)일수록 **여러 장비 조합**(우비+아이젠)을 요구 → 빌드 깊이. HP 풀-빌드(헬멧+패딩+장갑+대형배낭 = +23)는 캡 120에서 클립되므로, 남는 슬롯 가치는 면제·속도로 평가된다. 최대HP 증가 시 현재 HP도 같은 양 즉시 +.

## 4. 소비 시스템 (1회용) & 위협 대응

### 4.1 소비템 (등 슬롯 칸 수만큼 보유)

| 이름 | 효과 |
|---|---|
| 초코바 | HP +20 |
| 도시락 | HP +40 |
| 에너지젤 | 속도 +50% 10초 |
| 호루라기 | 다음 동물 피해 -50% (저가) |
| 곰 스프레이 | 다음 동물 피해 **무효** |
| 부적(소비) | 다음 환경 피해 1회 방어 |
| 응급키트 | HP +60, 모든 디버프 해제 |

### 4.2 환경 위협 → 장비 면제 (자동 처리)

> 등반 중 자동 발생. 장비 있으면 자동 면제(연출), 없으면 피해. 고도로 게이팅하여 에스컬레이션.

| 위협 | 출현 고도 | 효과 | 면제/완화 |
|---|---|---|---|
| 🌧 비 | 0m+ | HP 드레인 ×2 (8s) + 속도 ×0.5 | 우비(몸통) |
| 🪨 낙석 | 500m+ | HP -15 (즉시) | 헬멧 면제 / 등산모 -50% |
| 🧊 빙판 | 1000m+ | 속도 ×0.5 (6s) | 등산화/아이젠 |
| 🧗 절벽 | 1000m+ | HP -20 | 등산스틱 -50% |
| 🌨 눈보라 | 1000m+ | HP 드레인 ×3 + 속도 ×0.5 | **우비 + 아이젠** 둘 다 |
| 🥶 추위 | 1500m+ | HP 드레인 ×2 | 패딩 |
| ⚡ 번개 | 2000m+ | HP -30 | **막기 어려움** — 부적으로만 회피. 아이젠 장착 시 확률 ↑ |

### 4.3 동물 위협 → 소비 자동 대응 (멈춤 없음)

> 돌발성. 발생 시 **방어템이 가방에 있으면 자동 소모**(연출), 없으면 자동 피해. 멈추지 않는다.
> 자동 우선순위: 동물 피해가 큰 위협일수록 강한 방어템(스프레이>호루라기) 우선 소모.

| 동물 | 출현 고도 | 피해 | 자동 대응 |
|---|---|---|---|
| 🐍 뱀 | 0m+ | -20 | 호루라기(-50%)/스프레이(무효) 자동 소모 |
| 🐗 멧돼지 | 1000m+ | -30 | 호루라기/스프레이 자동 소모 |
| 🐻 곰 | 2000m+ | -50 | 곰 스프레이 자동 소모(없으면 큰 피해) |

> **설계 포인트**: 번개·곰은 장비로 완전 봉쇄되지 않게 남겨, 후반에도 HP/소비템이 끝까지 의미 있게. (아이젠↔번개 트레이드오프가 좋은 긴장)

## 5. 빌드 선택 화면 (멈춤)

### 5.1 장비 선택 — 게임이 멈추는 유일한 화면 (구조 "나" 채택)

**장비 구간(500m마다, 런당 6회)에서만** 게임이 멈추고 **3장 중 1택**. 소비는 멈춤 없이 자동 줍기(§1.2), 위협도 자동 처리.

**🛡 장비 구간 카드 풀**
| 카드 종류 | 비중 | 내용 |
|---|---|---|
| 🛡 장비 | 80% | 슬롯 장비 1종 (신규 슬롯/하위 티어 슬롯 우선 가중) |
| 📈 스탯 | 20% | 즉시 최대HP +N(캡 120) 또는 속도 +N |

- **장비 카드 가중 규칙**: 이미 T3로 채운 슬롯은 추첨 제외 → 항상 "쓸모 있는 업그레이드"가 뜨도록(빌드 정체 방지). 모든 슬롯이 천장이면 스탯/소비로 대체.
- 가끔(예: 1000·2000m 구간) **"장비 3종" 특수 선택**(구조 "가") → 빌드 우선순위 싸움. 기존 `generateSpecialEvent`(3지선다) 재활용.
- 고도 점프 카드는 **도입하지 않음**(위협 회피가 빌드 긴장을 약화).

**💊 소비는 선택 화면 없음**: 200m마다 자동으로 가방에 담기고(꽉 차면 약한 것 자동 교체), 사용도 자동(§1.2 자동화 규칙). 플레이어는 어떤 소비가 들어왔는지 알림으로만 확인.

### 5.2 콤보 시스템 재활용 (선택)

기존 콤보를 "**연속 위협 무피해 통과**" 스트릭으로 재해석 가능:
- 위협을 장비/소비로 연속 N회 무피해 통과 시 보너스(점수 또는 일시 버프).
- MVP에선 보류, 추후 도입.

## 6. 점수 (리더보드 유지)

```
총점 = 고도점수 + 생존보너스 + 속도보너스 + 장비보너스 + 무피해보너스 + 정복보너스
```

| 항목 | 공식(제안) |
|---|---|
| 고도점수 | 도달 고도(m) × 1 |
| 생존보너스 | floor(HP / 최대HP × 1000) |
| 속도보너스(승리 시) | max(0, (300 − 클리어초)) × 10 |
| 장비보너스 | 장착 장비 티어 합 × 50 |
| 무피해보너스 | 무피해 통과 위협 수 × 20 |
| 정복보너스(승리 시) | +1000 |

## 7. 데이터 모델 (구현 스케치)

> 기존 `src/types/meme-event.ts`의 `BuffType`/`ActiveBuff`/`ItemEffect` 엔진은 **재사용**한다. 아래는 신규 추가분.

```ts
// 장비 슬롯
export type EquipSlot = 'head' | 'body' | 'feet' | 'hands' | 'back' | 'accessory';

// 위협(환경/동물)
export type HazardType =
  | 'rain' | 'rockfall' | 'ice' | 'cliff' | 'blizzard' | 'cold' | 'lightning' // 환경
  | 'snake' | 'boar' | 'bear';                                                 // 동물

export interface EquipmentDef {
  id: string;
  name: string;
  slot: EquipSlot;
  tier: 1 | 2 | 3;
  maxHpBonus?: number;
  speedBonus?: number;
  consumableSlots?: number;       // back 전용
  immunities?: HazardType[];      // 완전 면제
  reductions?: Partial<Record<HazardType, number>>; // 0~1 피해 경감
  sideEffects?: { lightningChance?: number };       // 아이젠 등
  icon: string;
}

export interface ConsumableDef {
  id: string;
  name: string;
  effects: ItemEffect[];          // 기존 ItemEffect 재사용 (hp/buff/special…)
  counterAnimal?: number;         // 동물 피해 경감 0~1 (1=무효)
  blockEnvironment?: boolean;     // 환경 피해 1회 방어
  icon: string;
}

export interface HazardDef {
  type: HazardType;
  name: string;
  minAltitude: number;
  category: 'environment' | 'animal';
  hpDelta?: number;               // 즉시 피해(낙석/동물)
  drainMultiplier?: number;       // 드레인 배수(비/눈/추위)
  speedMultiplier?: number;       // 속도 배수
  durationSec?: number;           // 지속형 길이
  immuneIfHas: EquipSlot[] | 'special'; // 면제 판정 근거
  icon: string;
}

// 게임 상태 확장
export interface EquipmentState {
  equipped: Partial<Record<EquipSlot, EquipmentDef>>;
  consumables: ConsumableDef[];   // 길이 ≤ back.consumableSlots
  hazardsSurvivedNoHit: number;
}
```

### 7.1 면제 판정 (의사코드)

```ts
function resolveHazard(h: HazardDef, eq: EquipmentState): HazardOutcome {
  // 환경: 필요한 슬롯 장비가 다 있으면 면제
  if (h.category === 'environment') {
    const covered = h.immuneIfHas.every(slot => providesImmunity(eq.equipped[slot], h.type));
    if (covered) return { blocked: true, reason: eq.equipped /* 발동 장비 */ };
    // 부분 경감(헬멧 -50% 등) 적용
    return applyReductions(h, eq);
  }
  // 동물: 자동 — 방어템 있으면 자동 소모, 없으면 자동 피해 (멈춤 없음)
  return autoUseDefense(h, eq);
}
```

## 8. 기존 코드 매핑 (마이그레이션)

| 기존 | 처리 |
|---|---|
| `ALTITUDE_INCREASE_RATE = 25`(자동 등반) | **재해석** → `speed` 스탯(기본 25, 장비 가산). 값은 유지 가능 |
| `MAX_HP = 120`(시작값) | **변경** → 시작 100, **120은 하드 캡**으로 |
| `HP_DECREASE_RATE = 1`(시간 일정) | **변경** → 고도 구간별(0.3/0.5/0.8) |
| `EVENT_INTERVAL = 1.5`(1.5초 난사) | **변경** → 위협 6~8s 랜덤 / 장비선택 500m / 소비 200m 자동 |
| `generateDilemmaEvent`(랜덤 2지선다) | **대체** → 장비 카드 3장 생성기 + 위협 생성기 + 소비 자동 줍기로 분리 |
| `generateSpecialEvent`(3지선다, 미사용) | **재활용** → 특수 장비 선택 |
| `BuffType`/버프 엔진(`lib/buff.ts`) | **유지** → 갓생/존버/슬로우 등은 위협·소비 결과로 부여 |
| `weather`/`challenge` 카테고리 아이템 | **전환** → `HazardDef`로 흡수 |
| `supply`/`rest`/`gear` 아이템 | **전환** → 소비/장비 정의로 재배치 |
| 콤보(`lib/combo.ts`) | **보류/재해석**(무피해 스트릭) |
| `score.ts`, 리더보드, 결과 화면 | **유지** + 공식만 6장으로 갱신 |

## 9. MVP 범위 (1차 구현 목표)

**포함**
- 슬롯 3종: 몸통/발/등 (★)
- 장비 티어 각 2~3개 + 소비 4종(초코바·도시락·곰스프레이·응급키트)
- 위협 5종: 비·낙석·빙판·눈보라·곰
- 장비 선택(멈춤) @ 500m 구간, 카드 3장 + 소비 200m 자동 줍기
- 속도 기반 등반(기본 25) + 고도 비례 드레인 + HP 100/캡120
- 위협·동물·소비 전부 자동 처리
- 페이퍼돌(최소: 장착 아이콘 오버레이) + 위협 면제 연출
- 승/패 + 점수 + 리더보드 연동

**2차 이후**: 머리/손/액세서리 슬롯, 번개, 무피해 콤보, 풀 페이퍼돌 스프라이트, 캐릭터/스테이지 해금.

## 12. 아트 & 에셋 — 전면 픽셀 아트

> 게임 전체를 픽셀 아트로 통일. 기존 `specs/002-pixel-design-system`(픽셀 디자인 시스템)과 방향 일치.

### 12.1 페이퍼돌이란
캐릭터 몸(베이스) 위에 장비 조각을 **레이어로 겹쳐 그리는** 방식. 장비를 바꾸면 해당 레이어 스프라이트만 교체 → 겉모습이 실시간으로 변함. **"성장이 눈에 보이는"** 핵심 장치.

```
레이어 순서(아래→위): 베이스 몸 → 신발(발) → 옷(몸통) → 가방(등) → 장갑(손) → 모자(머리) → 액세서리
```
- MVP: 슬롯별 **아이콘 오버레이**(캐릭터 옆/위에 작은 픽셀 아이콘)로 시작 → 2차에서 **풀 레이어 스프라이트**.

### 12.2 무료 에셋 소스 (전부 상업적 사용 가능, 출처 표기만)
| 소스 | 라이선스 | 용도 |
|---|---|---|
| **Kenney.nl** | CC0 (출처 표기도 불필요) | UI, 아이템 아이콘, 이펙트, 폰트 — 최우선 추천 |
| **LPC (Liberated Pixel Cup)** / OpenGameArt | CC-BY-SA / GPL | **레이어드 캐릭터**(페이퍼돌 전용으로 설계됨) — 등산가 + 장비 레이어에 이상적 |
| **itch.io 무료 에셋팩** | 팩마다 다름(확인 필요) | 산/날씨/동물 배경·스프라이트 |
| **Pixel Art 아이콘팩** (game-icons.net 등) | CC-BY | 장비/소비/위협 아이콘 |

### 12.3 필요한 아트 목록 (MVP)
- **캐릭터**: 등산가 베이스 + 걷기 애니메이션 2~4프레임
- **장비 아이콘/레이어**: 몸통(바람막이·우비·패딩), 발(운동화·등산화·아이젠), 등(가방 3종) — MVP 슬롯
- **소비 아이콘**: 초코바·도시락·곰스프레이·응급키트
- **위협 연출**: 비·낙석·빙판·눈보라·곰 (이펙트 + 면제 시 "✅ 장비 발동" 팝업)
- **배경**: 고도별 산 타일(베이스캠프→설산), 패럴랙스 스크롤
- **UI**: HP 바·속도 미터·고도 게이지·장비 선택 카드 프레임 (Kenney UI팩)

> 액션 아이템: 각 소스에서 톤(팔레트·해상도, 예: 16×16 또는 32×32) 통일된 팩을 우선 선택. 톤 안 맞으면 후보정.
